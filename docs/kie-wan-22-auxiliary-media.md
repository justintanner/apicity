## Shared task-detail and callback contract

The shared task-detail page is [Get Task Details](https://docs.kie.ai/market/common/get-task-detail).
It defines:

- `GET https://api.kie.ai/api/v1/jobs/recordInfo?taskId=<taskId>` with the
  required query string `taskId`.
- Task states `waiting`, `queuing`, `generating`, `success`, and `fail`.
- The response’s `data` includes `taskId`, `model`, `state`, `param`,
  `resultJson`, `failCode`, `failMsg`, `costTime`, `completeTime`,
  `createTime`, `updateTime`, `progress`, and `creditsConsumed` (some are
  conditional). `param` is a JSON string containing the original request.
- For media/video output, successful `resultJson` is a JSON string containing
  `resultUrls`.
- KIE recommends callbacks for production, exponential backoff beginning at
  2–3 seconds when polling, a 10–15 minute polling timeout, and downloading
  result URLs promptly because they typically expire after 24 hours.

Each per-model OpenAPI document exposes the same `videoTaskCompleted` callback
at the supplied `callBackUrl`. Its request body requires `code`, `msg`, and
`data`; callback `code` is `200` for success or `501` for failure, and the
terminal `data.state` is `success` or `fail`. Callback `data` requires
`taskId`, `model`, `state`, `param`, `resultJson`, `failCode`, and `failMsg`;
`costTime`, `completeTime`, `createTime`, `updateTime`, and `creditsConsumed`
are also documented. Successful examples contain
`resultJson: {"resultUrls":["..."]}` while failed callbacks make
`resultJson`, `failCode`, and `failMsg` nullable.
